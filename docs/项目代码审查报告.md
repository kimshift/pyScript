## 一、项目概览

本项目用于对 **雷电模拟器(LDPlayer)多开器** 进行批量自动化操作，包括：批量创建/启动模拟器、批量设置（分辨率/内存）、批量安装 APK、开启/关闭同步、应用权限设置、模拟器备份/还原等。

**核心原理**：通过 `pyautogui` 截取屏幕 → `cv2.matchTemplate` 模板匹配定位按钮图片 → 模拟鼠标点击。坐标/图片路径集中在 `config.json` 与 `src/data.py`。

## 三、问题清单（按严重程度）

### 🔴 严重问题 —— 导致无法运行 / 直接故障

#### S1. `src/main.py` 导入错误，完全无法运行
- 位置：`src/main.py:5`、`:23`、`:29`
- 问题：`import common.device as device`、`import emulator.test as test`、`import emulator.start as start` —— `common`/`emulator` 是**模块(.py)**而非包，且不存在 `device`/`test`/`start` 子模块。
- 影响：`npm start`（`python src/main.py`）直接 `ModuleNotFoundError`。实际可用入口只有 `emulator.py` 的 `if __name__=='__main__'`。
- 建议：删除 `main.py` 中的无效导入与 `Progress` 类；若需保留入口，改写为 `from emulator import Main` + `Main().switch(case)`；或直接以 `emulator.py` 为唯一入口，`package.json` 的 `start` 改为 `python src/emulator.py`。

#### S2. `test/button.py` 导入错误
- 位置：`test/button.py:4`
- 问题：`from dictionaries import dict` —— 不存在 `dictionaries` 模块（应为 `src/data.py`），且 `dict` 遮蔽内置类型。
- 影响：测试脚本无法运行。
- 建议：改为 `import sys; sys.path.append('../src'); from data import BUTTONS`，并统一命名。

#### S3. 环境接线错误：`python` 命令指向无依赖的 3.13，项目真实环境是 Python 3.7
- 位置：`package.json:7`、`script/创建雷电.bat:3`、`script/启动雷电.bat:3`（均用裸 `python`）、`README.md:7`
- 问题：本机存在两个 Python —— 默认 `python` 解析到 WorkBuddy 自带 **3.13.12**（`C:\Users\PC-03-16\.workbuddy\binaries\python\versions\3.13.12`，**无项目依赖**）；项目真实开发环境是 **`D:\Program Files\Python37`（3.7.0）**，**依赖已全部装好**（PyAutoGUI/opencv-python/pyperclip/psutil/keyboard/APScheduler/numpy/Pillow）。`src` 模块在 3.7 下导入验证通过；`__pycache__` 残留 cpython-37 字节码也印证项目原本用 3.7。
- 影响：bat → `npm run create_ld` → `python src/emulator.py`，因 `python` 指向 3.13（无依赖）→ **`ModuleNotFoundError`**，脚本无法启动。项目并非"没装依赖"，而是**解释器没接对**。
- 建议（三选一）：
  1. **推荐**：把 bat / npm 脚本里的 `python` 显式改为 Python37 绝对路径（`D:\Program Files\Python37\python.exe`），并在 `.vscode/settings.json` 指定解释器；
  2. 或把依赖安装到 3.13（`python -m pip install pyautogui opencv-python pyperclip psutil keyboard APScheduler`）；
  3. 或调整系统 PATH，让 `python` 优先指向 Python37。
  同时新增 `requirements.txt` 固化依赖，更新 README 版本说明。
- 附加：`opencv-python-headless 5.0.0.93` 与 `opencv-python 4.10.0.84` 同时安装，headless 属冗余（服务器无 GUI 版），建议卸载 `opencv-python-headless` 避免版本冲突。

#### S4. `package.json` 的 `packages` 字段错误
- 位置：`package.json:17-22`
- 问题：`"packages": {"subprocess": "pip install subprocess", ...}` —— `packages` 不是 npm 标准字段（标准为 `dependencies`/`devDependencies`），npm 会直接忽略；且 `pip install subprocess` 会安装一个**与标准库同名**的无关 PyPI 包（`subprocess` 本就是标准库，无需安装）。
- 影响：安装指引无效且有误导性；README 中 `pip install subprocess pyautogui ...` 同样含此问题。
- 建议：删除 `packages` 字段，改为 `requirements.txt`；README 更新安装命令。

### 🟠 高优先级 —— 逻辑 / 健壮性缺陷

#### H1. 按钮坐标缓存失效（`Buttons.通用`）
- 位置：`src/common.py:309-318`
- 问题：先计算 `self.coord[self.btn]` 缓存，但 `:316` 又无条件 `coord = location(self.path, position)[:2]` **覆盖**缓存 → 缓存逻辑为死代码，每次点击都重新截图 + 模板匹配。
- 影响：与 commit `优化进程缓冲导致识别失败问题` 的意图相悖；每次点击都写盘截图、增加延迟与识别失败/误点概率；`self.coord` 预定义的 10 个按钮缓存形同虚设。
- 建议：命中缓存直接复用，未命中才 `location()` 并写入缓存：
  ```python
  coord = self.coord.get(self.btn)
  if not coord or coord[0] is None:
      coord = location(self.path, position)[:2]
      self.coord[self.btn] = coord
  ```

#### H2. 监听点击参数错配（`监听点击` → `wait_click`）
- 位置：`src/common.py:320-323` 与 `:170-172`
- 问题：`监听点击` 传入 `{'position': position, 'num': num}`，但 `wait_click` 读取 `config.get('number', 1)` —— key 是 `num` 而非 `number`，导致 `number` 恒为默认值 1。
- 影响：`listen=True` 时本应点击 `num` 次，实际只点击 **1 次**。
- 建议：统一 key，如 `wait_click(path, config)` 内 `config.get('num', 1)`；或 `监听点击` 改为 `{'position':..., 'number':num}`。

#### H3. `doubleClick` 参数错误
- 位置：`src/common.py:166`
- 问题：`pyautogui.doubleClick(interval)` —— 把 `interval` 当作 `x` 坐标传入（`doubleClick(x, y, interval=0.1)`）。
- 影响：当前未调用，属潜在 bug；一旦使用则点击坐标错误。
- 建议：`pyautogui.doubleClick(coord[0], coord[1], interval=interval)`。

#### H4. 裸 `except:` 吞掉异常
- 位置：`src/emulator.py:60-61`、`src/common.py:190-191`、`:359-360`
- 问题：`except:` 捕获所有异常，仅打印一句提示，无 traceback、无日志。
- 影响：定位/点击失败被静默吞掉，`batch_start` 中途出错仅打印"异常：终止执行"，问题难以排查。
- 建议：`except Exception as e:` 并 `traceback.print_exc()` 或写日志；至少记录异常对象。

#### H5. `close_running_process` 忙等无超时
- 位置：`src/common.py:29-30`
- 问题：`while is_process_running(process_name): pass` —— 若进程因权限/僵死无法终止，无限忙等，CPU 空转卡死。
- 建议：加超时（如 10s）与重试次数，超时后报错退出；使用 `proc.terminate()` 再 `kill()` 的降级策略。

#### H6. 备份/还原路径硬编码
- 位置：`src/emulator.py:241`、`:268`（`path = 'D:\\Program Files\\LDPlayer9\\backup'`）
- 问题：备份目录写死在代码中，与 `config.json` 的配置化设计不一致。
- 建议：在 `config.json` 增加 `backup_path` 字段并读取。

#### H7. `create_txt` 硬编码编号
- 位置：`src/emulator.py:281-294`
- 问题：`start=126, count=25, num=4` 硬编码，与 `config.json` 的 `emulator_end_id` 脱节。
- 影响：生成 `cache.txt` 的编号范围与真实模拟器 ID 无关；`cache.txt` 本身无任何代码消费（gitignore 也已忽略）。
- 建议：从 config 读取起止编号；确认 `cache.txt` 是否真的需要，否则移除该功能。

### 🟡 中优先级 —— 可读性 / 一致性 / 维护性

#### M4. 魔法数字与坐标硬编码

### 🟢 低优先级 —— 建议 / 可选优化

#### L1. 文件读写无异常处理
- `src/common.py:253-255` `read_json` 无 try/except，`config.json` 缺失或损坏直接崩溃；`write_json` 无末尾换行。
- 建议：加异常处理与默认值；`json.dump` 后补 `\n`。

#### L2. 批量设置连续点击无间隔
- `src/emulator.py:64-74` `batch_setting` 依次点击 8 个按钮，无 `sleep`，与 commit "点击按钮过快导致识别异常" 冲突，易因 UI 未就绪而漏点。
- 建议：每步加 `device.sleep(0.3~0.5)` 或采用"点击-确认-下一步"的显式校验。

#### L3. 文本输入方式
- `src/common.py:241-245` `write()` 按 `contains_chinese` 决定 `typewrite`/`paste`；`typewrite` 对特殊字符/非 ASCII 不可靠。
- 建议：统一走剪贴板 `paste()`（`pyperclip.copy` + `ctrl+v`），避免中文/符号输入丢失。

#### L4. gitignore 与生成物不一致
- `.gitignore:12` 忽略 `cache.txt`，但 `emulator.create_txt` 会重新生成；`cache.txt` 无代码消费。
- 建议：确认是否保留该生成物；不保留则删除 `create_txt` 与 `cache.txt`。

#### L5. 截图频繁写盘
- `src/common.py:59`、`:90` 每次定位都 `pyautogui.screenshot('screenshot.png')` 写盘；`wait_click` 循环中每帧写盘。
- 建议：`screenshot = pyautogui.screenshot()`（内存），仅调试时保存；`wait_click` 可降低轮询频率。
